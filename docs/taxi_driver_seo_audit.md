# Архитектура и план изменений — SEO-сайт водителей Яндекс Такси

Дата: 2026-11-14  
Исходное ТЗ: привлечение водителей (свой автомобиль), без аренды, без гарантированного дохода, не официальный сайт Яндекса.  
Примечание: вложенное ТЗ обрывается на «3.7. Ст» — план покрывает разделы 1–3.6; после получения полной версии документ уточнить.

---

## 1. Текущая архитектура

| Слой | Что есть |
|---|---|
| Стек | Rails 8.1, Ruby 3.4, PostgreSQL, Hotwire, Propshaft, Devise + Pundit (свой admin) |
| Домен | park-dostavka.ru; продукт исторически — курьеры Яндекс Еда |
| UI главной | Частично переведён на «Яндекс Такси» (`theme-taxi`, hero, CTA) |
| Контент / данные | В основном ещё курьерский: seeds, `CourierType`, `/goroda/…`, тексты Page |

### Уже есть и нужно сохранить

- **Заявки:** `Lead`, форма, UTM, rate-limit, thank-you, admin статусов
- **Рефералка:** `ReferralLink` / `ReferralClick`, `ReferralResolver`, `/go/register`
- **SEO:** `SeoMeta`, OG, schema, split sitemap, robots, `Redirect`, `SeoTemplate`
- **CMS-страницы:** `Page` + `PagesController` + admin (уже используется для `/usloviya-raboty/`)
- **Города:** `City` (+ declensions, indexable, featured), каталог `/goroda/`
- **Настройки:** `SiteSetting`, FAQ, отзывы, аналитика (Metrika/GA4 ID)

### Чего нет под новое ТЗ

| URL / сущность | Статус |
|---|---|
| `/` — тексты/блоки под «свой авто» | Частично (оболочка такси) |
| `/kak-ustroitsya/` | Нет |
| `/usloviya-raboty/` | Есть маршрут, контент курьерский → переписать |
| `/rabota-na-svoem-avto/` | Нет |
| `/trebovaniya-k-voditelyam/` | Нет |
| `/avtomobili-dlya-taksi/` + страницы моделей | Нет |
| Каталог авто (модель + admin) | Нет |
| Коммерческие условия парка как отдельные поля admin | Только через body Page / SiteSetting |

**Дублировать не будем:** City, Lead, Page, Referral*, SeoTemplate, SiteSetting.

## 2. Соответствие ограничениям ТЗ

| Ограничение | Сейчас | Действие |
|---|---|---|
| Только свой автомобиль | Не закреплено продуктово; есть пеший/вело курьер | Убрать аренду/чужой транспорт из оффера; фокус «свой авто» |
| Без аренды / проката / выкупа | Отдельных страниц нет | Не создавать; вычистить арендные формулировки из seeds |
| Без гарантированного заработка | В курьерских текстах есть дисклеймеры | Перенести на taxi-страницы; убрать «высокий доход» без оговорок |
| Не официальный сайт Яндекса | Есть в старых текстах | Явный дисклеймер в layout/footer + ключевые страницы |
| Условия из admin | Page body + SiteSetting | Переписать `/usloviya-raboty/`; при необходимости ключи SiteSetting для комиссий/выплат |
| Сохранить механизмы | — | Lead / referral / SEO / cities / admin без переписывания стека |

## 3. План изменений (поэтапно)

### Этап A — Каркас страниц (reuse `Page`)

1. Добавить маршруты (как у `usloviya-raboty`):
   - `/kak-ustroitsya`
   - `/rabota-na-svoem-avto`
   - `/trebovaniya-k-voditelyam`
2. Создать/обновить записи `Page` (seeds + admin): title, description, H1, body по ТЗ.
3. Переписать существующую `/usloviya-raboty/` под условия водителя (график, тарифы, комиссии, выплаты — только редактируемые факты).
4. Обновить nav/footer, sitemap `STATIC_PATHS`, schema breadcrumbs где нужно.

### Этап B — Главная `/`

1. Title / Description / H1 по ТЗ.
2. Блоки: как начать, преимущества (6 карточек), свой авто, требования, шаги, города, FAQ.
3. CTA: «Подключиться…» / «Узнать условия» + форма заявки (существующая).
4. Compliance: свой авто, без гарантий дохода, не официальный Яндекс.
5. Поля формы: город + телефон; `courier_type` — скрыть/зафиксировать под «водитель» или сделать опциональным без курьерских вариантов.

### Этап C — Каталог автомобилей (новая доменная сущность)

Модель `Vehicle` (или `CarModel`), поля из ТЗ:

- марка, модель, slug, год (от/до или год), класс, доступные тарифы, регион, примечание, источник, дата проверки
- SEO: title, description, H1, published, is_indexable

Публично:

- `GET /avtomobili-dlya-taksi` — список + поиск по марке/модели
- `GET /avtomobili-dlya-taksi/:slug` — карточка модели

Admin: CRUD + SEO. Sitemap: отдельный индекс или расширение pages.  
Публиковать только записи с проверенными данными (флаг / обязательные поля источника и даты проверки).

### Этап D — Контент и бренд-сдвиг Еда → Такси

1. Seeds / SeoTemplate / default SEO / referral URL (не `eda.yandex.ru` placeholder).
2. Тексты `/goroda/` — либо переписать под такси, либо временно noindex/редирект (решение продукта).
3. Судьба курьерских URL (`/rabota-*-kurerom/`, city×type): 301 / noindex / оставить как legacy — зафиксировать до реализации.
4. Admin brand: Park Admin → нейтральное имя таксопарка.

### Этап E — Доверие и конверсия

1. FAQ scopes под новые страницы.
2. CTA-блоки + lead form на каждой информационной странице.
3. Дисклеймеры, актуальные формулировки без неподтверждённых цифр возраста/стажа/комиссий.
4. Проверка аналитики (цели: CTA, submit, self-register).

---

## 4. Что не делаем

- Не меняем стек и не пишем приложение с нуля.
- Не клонируем City / Lead / Page.
- Не делаем разделы аренды, автопарка компании, «гарантированный заработок».
- Не выдаём сайт за официальный ресурс Яндекса.
- Не публикуем модели авто без источника и даты проверки.

3. Комиссии/выплаты парка: rich text на `/usloviya-raboty/` или отдельные `SiteSetting`?
4. Полный текст ТЗ с §3.7+ (сообщение обрывается) — есть ли ещё разделы (блог, калькулятор, юр. страницы)?

## 7. Статус внедрения (2026-11-14)

Сделано в коде (taxi-only):
- Маршруты информационных страниц ТЗ + 301 с курьерских URL
- Главная переписана под блоки ТЗ (свой авто, без гарантий дохода)
- Каталог `Vehicle` + admin + sitemap-vehicles
- Форма заявки без выбора типа курьера
- Nav/footer/дисклеймер партнёрского парка

```bash
docker compose exec web bundle exec rails db:migrate
docker compose exec web bundle exec rails taxi:seed_content
```
